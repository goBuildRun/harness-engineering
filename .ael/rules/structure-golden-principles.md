# 结构黄金原则（持续优化）

> GC 与 `structure_guard` 补充项。人类品味写入后机械执行。

## 放置

1. 新文件 **100%** 落在 active profile 的 package allowlist 内。
2. 模块依赖方向服从产品架构和 profile 不变式；Lifecycle core 不写死某一种服务分层。
3. 文件超过产品约定阈值时拆分或记录技术债；产品未定义时可用 400 行作为 review 提示，不作为跨语言硬规则。

## 优化（非新功能 PR 也可做）

4. 同一逻辑出现 **3 次** → 按产品架构提取到共享边界并补测试。
5. 接口、领域逻辑和数据契约按产品既有分层组织；具体目录由 profile 决定。
6. 删除未使用 import / 死函数（GC 扫描后确认）。

## 评审

7. QA 须核对：git 变更路径 ⊆ `03-实施方案` 登记路径。
8. 跨模块调用须遵守产品架构定义的公开契约，禁止绕过边界直接依赖内部实现。
